# График дежурств инженеров

Приложение для составления графика дежурств отдела с производственным календарём: смены, пятидневка, отпуска, переработка, статистика и экспорт в Excel.

В репозитории две версии:

- **desktop** — Python + PySide6 (`grafik_dezhurstv.py`);
- **web** — приложение на HTML/CSS/JS (`index.html` + `web/`); страницы статические и подходят для GitVerse Pages, синхронизация идёт в общую Postgres-базу по HTTPS, а какая именно база — зависит от адреса страницы (см. раздел «Общая база»).

Опубликованные веб-версии: <https://gmarkov.gitverse.site/grafik_dezhurstv/> и <https://griwqa.github.io/duty-schedule/> — база Supabase; <https://duty-schedule-phi.vercel.app/> — база Neon.

## Возможности

- Автоматическая основа графика: суточники распределяются по дням месяца, ротация продолжается через границы месяцев. Модель не фиксирована — смены расставляются вручную.
- Роли сотрудников: суточник, 5-дневный график, доп. инженер (подмена); состав отдела задаётся кнопкой «+ Добавить инженера», у каждого есть должность и телефон.
- 5-дневный график: офис по будням, тип дня меняется на офис / удалёнку / выезд; можно поставить дежурство У / В / Н. Новому пятидневщику офис заполняется по будням автоматически; если в день есть и офис, и дежурство, ячейка показывается двумя цветами — например, о/В.
- Ручная правка графика: правый клик по ячейке, клавиша Delete (выходной), перетаскивание смен между датами. Суточникам доступны и смены пятидневки — офис, удалёнка, выезд.
- Переименование сотрудника, смена телефона и должности не пересобирают график: расставленные вручную смены сохраняются.
- В карточке сотрудника есть кнопка «Сформировать график заново»: она пересобирает строку только этого сотрудника в открытом месяце и не затрагивает остальных. Для пятидневщика это офис по будням, для суточника — автоматическая ротация; у суточника кнопка появляется при смене роли.
- Отпуск: кнопка «Назначить отпуск» в карточке сотрудника ставит смену «Отп» на выбранный диапазон дат открытого месяца.
- Перераспределение смен: кнопка «Перераспределить смены» под графиком открывает панель, где выбирается дата начала и порядок суточников — первый выходит в выбранный день, второй на следующий и так далее по кругу до конца месяца. Дни отпуска пропускаются; смены до выбранной даты не меняются.
- Переработка доступна сотруднику любой роли: правый клик по ячейке → «Переработка» задаёт часы сверх смены на конкретный день. В ячейке это показывается мягким янтарным градиентом поверх заливки смены (включая совмещённые дни вроде о/у) и часами в уголке «Nч»; в день без смены — отдельной градиентной заливкой с «N ч». Поле в карточке сотрудника добавляет общую сумму за месяц. Отдельной праздничной смены нет — суточники работают праздники обычными сутками (`С`); при включённой галочке «Учитывать праздники» такие дни обведены красной рамкой.
- Помесячный архив: каждый месяц хранится отдельно, ручные правки не теряются при переключении месяцев и перезагрузке.
- Новый месяц формируется автоматически один раз при переходе на него; ротация продолжается от последнего дежурного предыдущего месяца. Отдельная кнопка «Сформировать график» не нужна.
- Добавление, удаление и смена роли сотрудника, а также изменение часов смен не пересоздают график: смены остальных строк сохраняются.
- Проверка графика: отсутствие двух дежурных в один день, дублей дежурств С и подмен П у разных инженеров в один день и смен подряд. Подмена в день, когда суточник уже на смене, замечанием не считается. День с замечанием подсвечивается в шапке, список замечаний выводится под графиком.
- Дополнительные дежурства у пятидневщика и доп. инженера — только сутки (`С`) и подмена (`П`); совмещённый рабочий день показывается как `о/С` или `о/П`. Ночных, утренних, дневных и вечерних дежурств больше нет: в веб-версии эти коды нельзя выбрать ни в одном меню.
- Статистика: суточные, подмены, дополнительные сутки по будням и по выходам/праздникам, отпуск, 5-дневные, часы, переработка (дни + карточка), отклонение от нормы месяца и доплата по тарифам; внизу выводится строка «Итого».
- Тарифы: кнопка «Тарифы» задаёт две ставки за дополнительные сутки — в будни (по умолчанию 1500 ₽) и в выходной или праздник (2500 ₽). Доплата = количество суток × ставка подходящего дня и считается только для пятидневщиков и доп. инженеров; смены суточников в доплату не входят. Ставки хранятся в общих настройках и доступны всем при входе.
- Производственный календарь из JSON: праздники, выходные и сокращённые дни.
- Экспорт: `.xlsx` в обеих версиях; веб-сборщик пишет настоящий OOXML-пакет (ZIP с XML-частями) без внешних библиотек, поэтому файл открывается в Excel и LibreOffice как документ Office, а не как HTML-таблица. В веб-экспорте есть колонка «Телефон», статистика выводится справа от графика через пустой столбец, включает суточные смены, подмены, разбивку дополнительных суток по будням и выходам и доплату, не растягивает дни месяца. Ниже графика тем же листом кладётся дублирующая цветовая схема: имя и телефон одной ячейкой, дни месяца без букв — чёрный суточная смена, тёмно-синий подмена, голубой выходной или праздник, зелёный обычный день, ярко-голубой отпуск; столбцы дней совпадают с верхним блоком, строка легенды замыкает блок.

Телефон, отпуск, переработка, перераспределение смен и пересборка строки одного сотрудника реализованы в веб-версии.

## Веб-версия

Страницы веб-версии можно раздавать любым статическим сервером. Локальный запуск работает с базой Supabase напрямую по HTTPS, поэтому при нём нужен доступ в интернет.

```bash
python -m http.server 8765
```

Откройте <http://localhost:8765/>.

Важно: приложение использует ES-модули и `fetch`, поэтому открывать `index.html` двойным кликом (`file://`) нельзя — нужен HTTP-сервер.

Данные веб-версии:

1. **общая база** — основной график (см. раздел ниже); приложение читает её при открытии страницы и заново при каждом входе, поэтому актуальные данные из базы всегда важнее локальной копии;
2. `localStorage` этого браузера — только если сервер синхронизации недоступен или в нём ещё нет графика;
3. демо-справочник `data/engineers.json` — если в браузере ещё нет данных.

- при открытии страницы график закрыт: приложение просит пароль. Пароль редактирования — общий пароль базы; пароль просмотра открывает график только для чтения. Кнопка «Закрыть» закрывает график и показывает «До новых встреч!»;
- в режиме редактирования правки сохраняются на сервер синхронизации автоматически; пароль действует до перезагрузки страницы;
- график можно выгрузить кнопкой «Экспорт в Excel» (`.xlsx`, открывается в Excel и LibreOffice; телефоны сотрудников — отдельной колонкой; снизу к графику добавляется цветовая схема без букв — сутки чёрным, подмена тёмно-синим, выходные голубым, обычные дни зелёным);
- производственный календарь читается из `data/calendar_ГОД.json`;
- список доступных годов — в `data/calendars.json`;
- свой календарь можно загрузить кнопкой «Загрузить календарь» (JSON, формат ниже).

### Общая база

Общий график хранится в Postgres, доступ идёт через Data API (PostgREST): браузер вызывает RPC-функции `get_schedule` и `save_schedule` по HTTPS. Чтение открыто всем, запись защищена общим паролем: запрос уходит в RPC-функцию, та сверяет bcrypt-хеш и только после этого обновляет строку. Секретов в браузере нет — наружу отдаётся только публичный ключ `anon`, который не умеет ни читать таблицы, ни писать в них.

Базы две, они независимы, и какая нужна — решает адрес страницы:

| База | Какие адреса с ней работают | Как обращается браузер |
| --- | --- | --- |
| Supabase Postgres | `gmarkov.gitverse.site`, `griwqa.github.io`, локальный запуск | `POST https://<проект>.supabase.co/rest/v1/rpc/get_schedule` и `.../rpc/save_schedule`; CORS раздаёт сам Data API, прокси не нужен |
| Neon Postgres | только `duty-schedule-phi.vercel.app` | через серверлес-прокси `api/schedule.js` на том же адресе: `GET /api/schedule` и `POST /api/schedule`, а прокси уже получает анонимный токен Neon Auth и вызывает RPC |

База выбирается один раз при загрузке страницы и больше не меняется. Переключения между базами нет: не отвечает выбранная — приложение показывает «нет связи с сервером синхронизации» и остаётся на локальной копии браузера, на другую базу оно не уходит. Запись идёт в ту же базу, из которой читали.

**Две базы — это два отдельных графика.** Сводки между ними нет, правки переносят вручную, и только хеш пароля держат одинаковым в `app_secrets` обеих баз — иначе пароль подойдёт к одной из них.

Перенос делают в консоли браузера на странице `https://duty-schedule-phi.vercel.app/`: только она видит обе базы, свою через `/api`, а Supabase напрямую. Адрес и публичный ключ берут из `SUPABASE_URL` и `SUPABASE_KEY` файла `web/neon.js`.

Из Supabase в Neon:

```js
{
  const key = "<SUPABASE_KEY>";
  const src = await (await fetch("<SUPABASE_URL>/rest/v1/rpc/get_schedule", {
    method: "POST",
    headers: { "Content-Type": "application/json", apikey: key },
    body: "{}",
  })).json();
  await fetch("/api/schedule", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ password: "<общий пароль>", payload: src.payload }),
  });
}
```

Из Neon в Supabase:

```js
{
  const key = "<SUPABASE_KEY>";
  const src = await (await fetch("/api/schedule")).json();
  await fetch("<SUPABASE_URL>/rest/v1/rpc/save_schedule", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      apikey: key,
      Authorization: `Bearer ${key}`,
    },
    body: JSON.stringify({ p_password: "<общий пароль>", p_payload: src.payload }),
  });
}
```

Каждый блок выполняют целиком и по очереди: фигурные скобки нужны затем, чтобы `const` из одного блока не мешал запустить другой в той же консоли. После переноса перезагрузите страницу и войдите заново — копия подтянет данные из своей базы.

Прокси принимает запросы только со своего же адреса — круг источников задан списком `ALLOWED_ORIGINS` в `api/schedule.js`, поэтому случайно поправить не ту копию не получится: запрос с другого адреса не пройдёт проверку.

Использование в интерфейсе:

- при каждом открытии страницы появляется диалог «Вход в график»;
- при каждом входе — и для редактирования, и для просмотра — приложение заново загружает график с сервера синхронизации, поэтому правки, сделанные в другом браузере с того же адреса, видны сразу после входа; копии на разных адресах работают с разными базами и друг друга не видят;
- пароль редактирования — общий пароль базы. При входе он проверяется реальной записью в RPC `save_schedule`; после входа правки сохраняются автоматически через ~1,6 с;
- пароль просмотра задаётся в режиме редактирования кнопкой «Пароль просмотра». В общем графике хранится только PBKDF2-хеш (SHA-256, 150 000 итераций, случайная соль). В режиме просмотра недоступны правки смен, сотрудники, настройки и загрузка календаря; месяцы и годы переключаются — показываются только те, что уже есть в сохранённом графике, новый месяц в просмотре не формируется; экспорт в `.xlsx` работает;
- кнопка «Закрыть» без ввода пароля закрывает график и показывает «До новых встреч!»; вернуться можно кнопкой «Войти в график»;
- если сервер отклонил пароль при сохранении, приложение просит войти заново;
- строка состояния показывает источник, время последнего сохранения, пометку «не сохранено на сервере» и «режим просмотра».

Пароль редактирования хранится только в `localStorage` этого браузера и очищается при перезагрузке страницы; в общий график и репозиторий он не попадает. Хеш пароля просмотра лежит в общем графике, который читается без пароля, поэтому пароль просмотра должен быть достаточно длинным. Кто знает пароль редактирования, тот может менять общий график, поэтому передавайте его только участникам.

Первичная настройка:

1. **основная база (Supabase)** — создайте проект, откройте **SQL Editor** и выполните `db/supabase_schedule.sql`: он создаёт таблицы `schedule_state` и `app_secrets`, RPC `get_schedule` / `save_schedule`, закрывает таблицы RLS и выдаёт `execute` ролям `anon` / `authenticated`. Отдельный адрес и publishable-ключ (`SUPABASE_URL` / `SUPABASE_KEY` в `web/neon.js`) берутся из страницы Project Settings — другой настройки проекта не требуется; CORS тоже не настраивают: его раздаёт Data API.
2. **база Neon** — создайте проект, включите в нём **Data API** и **Neon Auth** (анонимный вход), выполните `db/neon_schedule.sql`.
3. Опубликуйте репозиторий на Vercel — каталог `api/` автоматически становится серверлес-функцией, дополнительная сборка не нужна. Отдельного адреса прокси в коде нет: приложение на `duty-schedule-phi.vercel.app` обращается к `/api` своего же домена.
4. Заведите пароль. Хеш обязан быть одинаковым в обеих базах, иначе один и тот же пароль подойдёт только к одной. В SQL-редакторе базы, где пароль уже работает, выполните `select password_hash from public.app_secrets where id = 'schedule';` и вставьте результат в `insert` из конца файла `db/supabase_schedule.sql` (или `db/neon_schedule.sql`). Пока хеш в базе не записан, `save_schedule` отвечает 503 «расписание ещё не выпущено», и правки в эту базу не сохраняются.
5. Замените пароль — только если он и так утекал в логи: тогда одинаковый новый хеш нужно записать в `app_secrets` обеих баз, иначе пароль в одной перестанет подходить к другой.

**Зачем развязка.** Раньше одна страница сначала пробовала основную базу, а при таймауте переходила на резерв. Это спасало доступность, но данные расходились молча: сессия, ушедшая в резерв, писала в него, а все остальные продолжали видеть основную базу и не знали об этом. Теперь у каждой копии ровно одна база, её поведение предсказуемо, а расхождение — это сознательный шаг «перенести вручную», а не следствие таймаута. Пустая база при этом отвечает HTTP 200 с телом `null`: это не сбой, а состояние «графика ещё нет», и при первом входе с паролем редактирования график будет в неё записан.

Особенности: запись работает по принципу «последний сохранивший прав»; прямые запросы к таблицам закрыты RLS и отозванными правами, доступны только RPC; размер сохраняемого JSON ограничен 1 МБ; при смене пароля обновите хеш в `app_secrets` обеих баз. Бесплатный проект Supabase ставится на паузу через неделю без запросов, поэтому `.github/workflows/keep-alive.yml` раз в сутки вызывает `get_schedule` публичным ключом: без него копии с GitVerse и GitHub Pages перестали бы сохранять правки. Если база недоступна, приложение показывает «нет связи с сервером синхронизации» и работает с локальной копией браузера; статические страницы зеркал при этом открываются как обычно.

Прокси базы Neon — `api/schedule.js`: секретов не хранит, анонимный токен Neon Auth получает на сервере, адреса обращений к Neon переопределяются env-переменными `NEON_DATA_API_URL` и `NEON_AUTH_URL`, а круг разрешённых источников задаёт список `ALLOWED_ORIGINS` в том же файле.

Старый `data/shared.json` больше не используется приложением: общий график живёт в базе.

Чтобы добавить календарь нового года в опубликованное приложение:

1. положите файл `data/calendar_2028.json`;
2. добавьте `2028` в массив `years` файла `data/calendars.json`;
3. опубликуйте изменения.

## Desktop-версия

Требования: Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python grafik_dezhurstv.py
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python grafik_dezhurstv.py
```

Desktop-версия хранит справочник сотрудников в `data/engineers.json`, а локальные настройки — в `data/settings.json` (файл исключён из репозитория).

## Публикация на GitVerse Pages

GitVerse Pages — это хостинг статических сайтов из репозитория. Веб-версия полностью статическая, поэтому работает на Pages; desktop-версия на Python там не запускается (Pages не выполняет серверный код).

1. Создайте **публичный** репозиторий на <https://gitverse.ru/> и включите в нём CI/CD.
2. Запушьте проект в ветку `main`.
3. Откройте **«Настройки → Страницы»**, включите GitVerse Pages, выберите источник «Ветка», ветку `main` и корневую папку (`/`), сохраните.
4. Дождитесь сборки — сайт откроется по адресу `https://<владелец>.gitverse.site/<репозиторий>/`.

Файл `.nojekyll` в корне отключает обработку Jekyll: сайт публикуется как есть. Все пути к стилям, скриптам и данным относительные (`./web/...`, `./data/...`), поэтому приложение работает и в подкаталоге репозитория.

Ограничения Pages: только статика, размер сборки до 500 МБ. Общий график загружается с сервера синхронизации в момент открытия страницы, поэтому изменения графика не требуют пересборки; `localStorage` хранит локальную копию; пароль редактирования — только до перезагрузки страницы.

Серверная часть на Pages не размещается: общая база — внешний Postgres, к которому браузер обращается напрямую по HTTPS (см. раздел «Общая база»), а страницы GitVerse/GitHub Pages остаются статическими. Учтите, что репозиторий публичный: `data/engineers.json` доступен всем, не добавляйте в него персональные данные, если они не должны быть открыты. Общий график в базе тоже читается всеми без пароля — пароль защищает только запись.

## Обозначения смен

| Код | Смена | Часы |
| --- | --- | --- |
| `С` | суточная, 10:00–10:00 | 24 |
| `П` | подмена — дополнительные сутки пятидневщика или доп. инженера | 24 |
| `о` | офис (5-дневный график) | 8 |
| `у` | удалёнка (5-дневный график) | 8 |
| `в` | выезд (5-дневный график) | 8 |
| `Отп` | отпуск | 0 |

Ночные (`Н`), утренние (`У`), дневные (`Д`) и вечерние (`В`) дежурства веб-версия больше не предлагает: их нет в меню ячейки, в тарифах и в статистике. Коды остаются в desktop-версии и в сохранённых месяцах, где они были проставлены; в Python-ядре `П` исторически означало праздничную смену, в веб-версии это подмена.

Переработка задаётся двумя способами и прибавляется к часам месяца: правый клик по ячейке → «Переработка» (часы сверх смены на конкретный день; в ячейке — янтарный градиент поверх смены, включая о/у, и часы; в день без смены — отдельная градиентная заливка) и поле «Переработка за месяц» в карточке сотрудника.

Праздничные дни в строках сотрудников обведены красной рамкой; смена при этом остаётся обычной.

Часы суточной и 5-дневной смен меняются в «Настройках смен», ставки за дополнительные сутки — в «Тарифах». Поле часов ночной смены из настроек убрано вместе с самой ночной сменой; в сохранённых старых месяцах `nightHours` по-прежнему учитывается, а при его отсутствии считается 15 ч.

## Формат производственного календаря

```json
{
  "2026-11-03": { "weekend": false, "holiday": false, "short": true },
  "2026-11-04": { "weekend": false, "holiday": true, "short": false }
}
```

- `holiday` — праздничный день; смена остаётся обычной (кода `П` нет), день отмечен красным в шапке и красной рамкой в строке сотрудника.
- `short` — сокращённый день: норма месяца уменьшается на 1 час.
- Если даты нет в файле, выходной определяется по дню недели (сб/вс), праздник — нет.

## Тесты JS-логики

`web/core.js` — порт Python-алгоритмов. Тесты сравнивают результаты с эталоном, рассчитанным Python-версией.

```bash
python web/tests/make_reference.py
node web/tests/core.test.mjs
node web/tests/substitute.test.mjs
node web/tests/xlsx.test.mjs
```

`web/tests/substitute.test.mjs` проверяет дополнительные дежурства: подмена считается полными сутками, `extraDutyTotals` разделяет будни и выходные/праздники (и иначе, когда учёт праздников выключен), суточник в доплату не попадает, а валидатор не считает подмену за суточником конфликтом.

`web/tests/xlsx.test.mjs` проверяет выгрузку: файл обязан быть ZIP-архивом с XML-частями OOXML (сигнатура, состав частей, CRC32 каждой части, стили и экранирование), а не HTML-таблицей с расширением Excel.

Пересоздавать `reference.json` нужно после изменения Python-алгоритмов. Для запуска тестов достаточно Node.js 18+; для самого приложения Node не требуется.
