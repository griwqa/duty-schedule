# График дежурств инженеров

Приложение для составления графика дежурств отдела с производственным календарём: смены, пятидневка, отпуска, переработка, статистика и экспорт в Excel.

В репозитории две версии:

- **desktop** — Python + PySide6 (`grafik_dezhurstv.py`);
- **web** — приложение на HTML/CSS/JS (`index.html` + `web/`); страницы статические и подходят для GitVerse Pages, общая синхронизация идёт через серверлесс-прокси `api/` на Vercel.

Опубликованная веб-версия: <https://gmarkov.gitverse.site/grafik_dezhurstv/>.

## Возможности

- Автоматическая основа графика: суточники распределяются по дням месяца, ротация продолжается через границы месяцев. Модель не фиксирована — смены расставляются вручную.
- Роли сотрудников: суточник, 5-дневный график, доп. инженер (подмена); состав отдела задаётся кнопкой «+ Добавить инженера», у каждого есть должность и телефон.
- 5-дневный график: офис по будням, тип дня меняется на офис / удалёнку / выезд; можно поставить дежурство У / В / Н. Новому пятидневщику офис заполняется по будням автоматически; если в день есть и офис, и дежурство, ячейка показывается двумя цветами — например, о/В.
- Ручная правка графика: правый клик по ячейке, клавиша Delete (выходной), перетаскивание смен между датами. Суточникам доступны и смены пятидневки — офис, удалёнка, выезд.
- Переименование сотрудника, смена телефона и должности не пересобирают график: расставленные вручную смены сохраняются.
- В карточке сотрудника есть кнопка «Сформировать график заново»: она пересобирает строку только этого сотрудника в открытом месяце и не затрагивает остальных. Для пятидневщика это офис по будням, для суточника — автоматическая ротация; у суточника кнопка появляется при смене роли.
- Отпуск: кнопка «Назначить отпуск» в карточке сотрудника ставит смену «Отп» на выбранный диапазон дат открытого месяца.
- Перераспределение смен: кнопка «Перераспределить смены» под графиком открывает панель, где выбирается дата начала и порядок суточников — первый выходит в выбранный день, второй на следующий и так далее по кругу до конца месяца. Тип смены (Н или С) сохраняется по дням, дни отпуска пропускаются; смены до выбранной даты не меняются.
- Переработка доступна сотруднику любой роли: правый клик по ячейке → «Переработка» задаёт часы сверх смены на конкретный день. В ячейке это показывается мягким янтарным градиентом поверх заливки смены (включая совмещённые дни вроде о/у) и часами в уголке «Nч»; в день без смены — отдельной градиентной заливкой с «N ч». Поле в карточке сотрудника добавляет общую сумму за месяц. Отдельной праздничной смены «П» больше нет — суточники работают праздники обычными сутками; при включённой галочке «Учитывать праздники» такие дни обведены красной рамкой.
- Помесячный архив: каждый месяц хранится отдельно, ручные правки не теряются при переключении месяцев и перезагрузке.
- Новый месяц формируется автоматически один раз при переходе на него; ротация продолжается от последнего дежурного предыдущего месяца. Отдельная кнопка «Сформировать график» не нужна.
- Добавление, удаление и смена роли сотрудника, а также изменение часов смен не пересоздают график: смены остальных строк сохраняются.
- Проверка графика: отсутствие двух дежурных в один день, дублей дежурств У / Д / В / Н / С у разных инженеров в один день и смен подряд. День с замечанием подсвечивается в шапке, список замечаний выводится под графиком.
- День (Д) доступен суточнику как переработка в будний день и пятидневщику в выходной или отпуск; на рабочем дне пятидневщика показывается совмещённо как о/Д.
- Статистика: утро, день, вечер, ночные, суточные, отпуск, 5-дневные, часы, переработка (дни + карточка), отклонение от нормы месяца и доплата по тарифам; внизу выводится строка «Итого».
- Тарифы: кнопка «Тарифы» задаёт ставку за смену для У / Д / В / Н; доплата в статистике считается как количество смен × ставка. Ставки хранятся в общих настройках и доступны всем при входе.
- Производственный календарь из JSON: праздники, выходные и сокращённые дни.
- Экспорт: `.xlsx` в desktop-версии, `.xls` (HTML-таблица) в веб-версии; в веб-экспорте статистика выводится справа от графика через пустой столбец, включает колонки У / Д / В и доплату, не растягивает дни месяца.

Телефон, отпуск, переработка, перераспределение смен и пересборка строки одного сотрудника реализованы в веб-версии.

## Веб-версия

Страницы веб-версии можно раздавать любым статическим сервером. Общая синхронизация работает через прокси на Vercel, поэтому при локальном запуске нужен доступ в интернет.

```bash
python -m http.server 8765
```

Откройте <http://localhost:8765/>.

Важно: приложение использует ES-модули и `fetch`, поэтому открывать `index.html` двойным кликом (`file://`) нельзя — нужен HTTP-сервер.

Данные веб-версии:

1. **Neon** — общая база (см. раздел ниже); приложение читает её при открытии страницы и заново при каждом входе, поэтому актуальные данные из базы всегда важнее локальной копии;
2. `localStorage` этого браузера — только если сервер синхронизации недоступен или в нём ещё нет графика;
3. демо-справочник `data/engineers.json` — если в браузере ещё нет данных.

- при открытии страницы график закрыт: приложение просит пароль. Пароль редактирования — общий пароль Neon; пароль просмотра открывает график только для чтения. Кнопка «Закрыть» закрывает график и показывает «До новых встреч!»;
- в режиме редактирования правки сохраняются в Neon автоматически; пароль действует до перезагрузки страницы;
- график можно выгрузить кнопкой «Экспорт в Excel» (`.xls`, открывается в Excel и LibreOffice);
- производственный календарь читается из `data/calendar_ГОД.json`;
- список доступных годов — в `data/calendars.json`;
- свой календарь можно загрузить кнопкой «Загрузить календарь» (JSON, формат ниже).

### Общая база Neon

Общий график хранится в Neon Postgres, доступ к нему идёт через Neon Data API (PostgREST) с анонимным JWT из Neon Auth. Чтение открыто всем, запись защищена общим паролем: прокси отправляет его в RPC-функцию, та сверяет bcrypt-хеш и только после этого обновляет строку.

Браузер не обращается к Neon напрямую: веб-приложение ходит в серверлесс-прокси `api/schedule.js` на Vercel (`GET /api/schedule` — чтение, `POST /api/schedule` — сохранение), а уже прокси получает анонимный токен и вызывает RPC. Поэтому работа приложения не зависит от доступности доменов `*.neon.tech` с компьютера пользователя, а CORS настроен на стороне прокси — все зеркала (GitVerse Pages, Vercel, GitHub Pages) работают с одной базой. Прокси не хранит секретов: ему нужен только тот же анонимный токен, что раньше получал браузер.

Использование в интерфейсе:

- при каждом открытии страницы появляется диалог «Вход в график»;
- при каждом входе — и для редактирования, и для просмотра — приложение заново загружает график через прокси, поэтому правки, сделанные в другом браузере или на другом домене, видны сразу после входа;
- пароль редактирования — общий пароль Neon. При входе он проверяется реальной записью в RPC `save_schedule`; после входа правки сохраняются автоматически через ~1,6 с;
- пароль просмотра задаётся в режиме редактирования кнопкой «Пароль просмотра». В общем графике хранится только PBKDF2-хеш (SHA-256, 150 000 итераций, случайная соль). В режиме просмотра недоступны правки смен, сотрудники, настройки и загрузка календаря; экспорт в Excel работает;
- кнопка «Закрыть» без ввода пароля закрывает график и показывает «До новых встреч!»; вернуться можно кнопкой «Войти в график»;
- если сервер отклонил пароль при сохранении, приложение просит войти заново;
- строка состояния показывает источник, время последнего сохранения, пометку «не сохранено на сервере» и «режим просмотра».

Пароль редактирования хранится только в `localStorage` этого браузера и очищается при перезагрузке страницы; в общий график и репозиторий он не попадает. Хеш пароля просмотра лежит в общем графике, который читается без пароля, поэтому пароль просмотра должен быть достаточно длинным. Кто знает пароль редактирования, тот может менять общий график, поэтому передавайте его только участникам.

Первичная настройка проекта Neon:

1. создайте проект и включите в нём **Data API** и **Neon Auth** (анонимный вход);
2. опубликуйте репозиторий на Vercel — каталог `api/` автоматически становится серверлес-функцией, дополнительная сборка не нужна. При желании адреса Neon можно переопределить env-переменными `NEON_DATA_API_URL` и `NEON_AUTH_URL`;
3. выполните `db/neon_schedule.sql` — он создаёт таблицы `schedule_state` и `app_secrets`, RPC `get_schedule` / `save_schedule` и выдаёт `execute` ролям `anonymous` / `authenticated`;
4. в SQL замените `CHANGE_ME` на свой пароль (или обновите `app_secrets` вручную) и передайте этот пароль участникам.

Особенности: запись работает по принципу «последний сохранивший прав»; прямые запросы к таблицам закрыты RLS и отозванными правами, доступны только RPC; размер сохраняемого JSON ограничен 1 МБ; при смене пароля обновите хеш в `app_secrets`. Прокси — единая точка входа: если он недоступен, синхронизация не работает (статические страницы зеркал при этом открываются как обычно), а интерфейс показывает «нет связи с сервером синхронизации».

Зеркала прокси перечислены в массиве `SYNC_ENDPOINTS` файла `web/neon.js`: приложение по очереди пробует каждый адрес и останавливается на первой успешной ответившей ручке (ошибки 400/401 не повторяет на других адресах — это неверный пароль или пустой запрос). Если рабочая сеть блокирует `*.vercel.app`, достаточно задеплоить тот же `api/schedule.js` на любой доступный хостинг с серверными функциями и добавить его адрес в `SYNC_ENDPOINTS` — сам код прокси менять не нужно, он не содержит секретов.

Старый `data/shared.json` больше не используется приложением: общий график живёт в Neon.

Чтобы добавить календарь нового года в опубликованное приложение:

1. положите файл `data/calendar_2028.json`;
2. добавьте `2028` в массив `years` файла `data/calendars.json`;
3. опубликуйте изменения.

## Desktop-версия

Требования: Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python grafik_dezhurstv.py
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python grafik_dezhurstv.py
```

Desktop-версия хранит справочник сотрудников в `data/engineers.json`, а локальные настройки — в `data/settings.json` (файл исключён из репозитория).

## Публикация на GitVerse Pages

GitVerse Pages — это хостинг статических сайтов из репозитория. Веб-версия полностью статическая, поэтому работает на Pages; desktop-версия на Python там не запускается (Pages не выполняет серверный код).

1. Создайте **публичный** репозиторий на <https://gitverse.ru/> и включите в нём CI/CD.
2. Запушьте проект в ветку `main`.
3. Откройте **«Настройки → Страницы»**, включите GitVerse Pages, выберите источник «Ветка», ветку `main` и корневую папку (`/`), сохраните.
4. Дождитесь сборки — сайт откроется по адресу `https://<владелец>.gitverse.site/<репозиторий>/`.

Файл `.nojekyll` в корне отключает обработку Jekyll: сайт публикуется как есть. Все пути к стилям, скриптам и данным относительные (`./web/...`, `./data/...`), поэтому приложение работает и в подкаталоге репозитория.

Ограничения Pages: только статика, размер сборки до 500 МБ. Общий график загружается через прокси в момент открытия страницы, поэтому изменения графика не требуют пересборки; `localStorage` хранит локальную копию; пароль редактирования — только до перезагрузки страницы.

Серверная часть на Pages не размещается: синхронизация живёт в прокси на Vercel (см. раздел «Общая база Neon»), а страницы GitVerse/GitHub Pages остаются статическими. Учтите, что репозиторий публичный: `data/engineers.json` доступен всем, не добавляйте в него персональные данные, если они не должны быть открыты. Общий график в Neon тоже читается всеми без пароля — пароль защищает только запись.

```text

```

## Обозначения смен

| Код | Смена | Часы |
| --- | --- | --- |
| `Н` | ночная, 19:00–10:00 | 15 |
| `С` | суточная, 10:00–10:00 | 24 |
| `У` | утро | не суммируются |
| `Д` | день | не суммируются |
| `В` | вечер | не суммируются |
| `о` | офис (5-дневный график) | 8 |
| `у` | удалёнка (5-дневный график) | 8 |
| `в` | выезд (5-дневный график) | 8 |
| `Отп` | отпуск | 0 |

Переработка задаётся двумя способами и прибавляется к часам месяца: правый клик по ячейке → «Переработка» (часы сверх смены на конкретный день; в ячейке — янтарный градиент поверх смены, включая о/у, и часы; в день без смены — отдельная градиентная заливка) и поле «Переработка за месяц» в карточке сотрудника.

Праздничные дни в строках сотрудников обведены красной рамкой; смена при этом остаётся обычной.

Часы ночной, суточной и 5-дневной смен можно изменить в «Настройках смен».

## Формат производственного календаря

```json
{
  "2026-11-03": { "weekend": false, "holiday": false, "short": true },
  "2026-11-04": { "weekend": false, "holiday": true, "short": false }
}
```

- `holiday` — праздничный день; смена остаётся обычной (кода `П` нет), день отмечен красным в шапке и красной рамкой в строке сотрудника.
- `short` — сокращённый день: норма месяца уменьшается на 1 час.
- Если даты нет в файле, выходной определяется по дню недели (сб/вс), праздник — нет.

## Тесты JS-логики

`web/core.js` — порт Python-алгоритмов. Тесты сравнивают результаты с эталоном, рассчитанным Python-версией.

```bash
python web/tests/make_reference.py
node web/tests/core.test.mjs
```

Пересоздавать `reference.json` нужно после изменения Python-алгоритмов. Для запуска тестов достаточно Node.js 18+; для самого приложения Node не требуется.
